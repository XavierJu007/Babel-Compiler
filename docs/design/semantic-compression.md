# Babel-Compiler 高密度巴别语与用户词典设计

> 更新日期：2026-11-20。定位是使用者自行维护专业词典的高密度语义编译小工具。
> 使用方式见[领域表达库](../usage/domain-library.md)、[Token 计数](../usage/token-counting.md)和[验证模式](../usage/validation.md)；近期范围见[路线图](../plans/ROADMAP.md)。

## 1. 目标与范围

Babel 将自然语言中展开成句子的关系压成高密度巴别语：保留实体，默认用混合语言浅树表达动作、对象、条件、作用域与约束，主动采用含义明确的公开术语、常用缩写和符号。输出不要求完整句子；编译应重组关系与共享条件，避免只做同义词替换或句子润色。简单单关系可以保持一行。

使用者提供自己熟悉的专业术语、适用条件和例子。工具用一套固定规则组合相关词条、生成候选、计数，并提供可选验证和代理回退。Web、CLI、API 和代理使用相同规则；专业词典为空时，公共关系表达仍应生效。

目标按以下顺序处理：

1. 保留任务、事实、主体、关系、条件、范围和不确定性，不擅自增加业务要求。
2. 输出脱离编译提示词和词典后仍可理解。
3. 在保留信息的前提下，减少所选目标编码下的文本 token。

“更大语义空间”指在同样的文本预算内保留更多有用信息，不改变模型的上下文上限或参数规模。“领域引导”指使用准确的公开术语限定语境，不承诺精确激活某组参数或专家。

专业内容由使用者维护。内置词条提供起点和编辑示例，项目不承担建设覆盖所有行业的专业知识库。使用者只需维护与自己的文本有关的少量条目。

## 2. 两条输出底线

### 不使用私有码本

禁止把一段内容替换成新造的 `A17`，再让消费模型查询映射表恢复。也不能把公共符号改成项目私有含义，例如规定 `@` 代表“认证成功”。原文已有变量、字段名和标准术语可以保留；原文中的 `x` 不因单字母而自动成为私有码本。

词条的内部 `id` 只用于管理，不作为输出中的实体代号。公共符号只能使用工具目录中的固定含义；适用业务语境写在词条条件里。

### 无图例自解释

最终文本应独立包含理解任务所需的实体、关系和约束。消费模型无需接收词典、编译提示词或额外图例，也无需学习私有的 Babel 语法。自解释要求关系可恢复，不要求把它们重新展开成自然语言段落。

例如，`金额>=5000元: 须主管批准` 保留了对象、边界、单位和义务；`¬删除` 只否定删除这一命题，不能替代明确的 `禁止删除`，也不能自行表达“尚未”的时间含义。`禁止删除`、`仅当`、`顺序:` 是为关系消歧的短标签，可以与符号一起使用。

这是输出要求，不是对任意模型的普遍保证。模型验证通过只表示本次检查未发现问题；出现无法确定的含义时，应保留原文或报告问题。

## 3. 用户词典与固定表达规则

| 组成部分 | 职责 |
| --- | --- |
| 公共编译规则 | 保留原意、保护技术字面量、禁止私有码本、要求自解释 |
| 用户领域词典 | 提供术语、适用条件、保留项、不可混淆关系、公共符号和示例 |
| 固定表达规则 `mixed` | 多分支默认生成混语浅树，优先用 `role` / `goal` 等短标签，主动组合公共符号与必要短语，由项目统一维护 |
| 目标计数配置 | 指定估算或具体编码，独立于编译模型选择 |

使用者选择自己的领域词典，无需选择或编辑输出预设。编译器只取与当前文本相关的条目；词条中的条件是改写参考，不能据此补充原文没有的事实或最佳实践。

编译模型的 `system` 消息只包含固定编译规则。原文以 `original`、所选领域资料以 `domain_guidance` 放入同一条 `user` 消息的独立 JSON 字段；重组时另加 `candidate` 失败草稿。领域资料按不可信数据处理，不再拼进系统指令。JSON 字段隔离避免结构上的指令提权，但不能证明任意模型都不会被资料内容误导；模型对照与独立盲读仍需使用可信服务。

下面是一个词条片段，完整领域文件结构和编辑方法见[领域表达库](../usage/domain-library.md)：

```json
{
  "id": "authorization",
  "canonical": "授权",
  "aliases": ["操作权限校验"],
  "triggers": ["访问权限"],
  "use_when": ["原文要求判断主体是否有权对资源执行某项动作"],
  "preserve": ["主体、资源和动作", "原文给出的范围、允许条件和拒绝行为"],
  "do_not_merge_with": ["认证", "登录状态校验"],
  "symbols": [],
  "examples": [{
    "input": "登录成功后，仍需校验用户是否有权删除该订单",
    "output": "登录成功后: 仍须校验用户对该订单的删除权限"
  }]
}
```

别名是有适用条件的表达参考，不是全局字符串替换规则。例子用于说明什么信息必须保留，不保证候选一定更短。通用词条检查和模型验证也不能代替使用者对专业含义的判断。

## 4. 表达与语义保护

固定策略先提取任务中的实体和关系，再用浅树组织共享主体、前提和动作。原文章节属于输入布局，输出按实际依赖重新组织：将跨章节前置条件和异常绑定到对应动作，共享主体和全局限制提升到父节点，只写一次；叶子保留分支特有的关系。执行先后单列为短链，不依赖原章节编号暗示顺序。原六章改成六个短标题、加冒号或加树枝后逐条缩句，仍不符合目标。

| 原关系 | 可采用的紧凑表达 |
| --- | --- |
| 检查每个订单是否属于待处理订单集合 | `∀订单: 检查订单∈待处理订单集合` |
| 先读取缓存，再查询数据库 | `顺序: 读取缓存→查询数据库` |
| 仅当用户已登录且拥有编辑权限，才允许修改文档 | `允许用户修改文档，仅当用户已登录∧有编辑权限` |
| 因为数据源不可用，报告暂缓发布 | `暂缓发布∵数据源不可用` |
| 对所有报告，必须脱敏其中的凭据和个人信息 | `∀报告: 须脱敏{凭据,个人信息}` |
| 输出中文的 Markdown 表格 | `输出: 中文 Markdown表格` |

这些是树节点或叶子中的公共关系示意，不定义新的符号码本。`|` 可用于边界明确的枚举；`∧` 表达同时成立，`∨` 表达逻辑或，不能把“全部执行”误写成“任选其一”。多分支正文默认浅树，短行与括号补充叶子的作用域；简单单关系不必增加根节点。树枝应表达共同条件和动作归属，不能只装饰原章节。

改写应保留以下区别：

- 主体和对象、必要与充分条件、原因与顺序。
- 事实否定、禁止、许可、义务、免除义务和建议。
- 量词、范围、例外、先后次序及其绑定的动作。
- 数值、比较符、单位和它们约束的对象。
- null、空字符串、空集合和字段缺失。
- 确定事实、可能性、未验证猜测和引用内容。

字段名、路径、代码、正则、命令、协议值和固定返回值按原值保护；不能为排版统一而改动其内容。标示固定返回值的装饰性引号可以变化，交由模型判断语义；明确逐字要求、实际 JSON 字符串及其转义仍完整保护。

引号本身不构成字节保护：普通自然语言条件 `「已签收未超过 7 天」` 可压为 `签收≤7天`，活动描述 `参与「满 3 件 8 折」` 可压为 `参与(满3件8折)`，仍须保留条件、数值和作用域。被编译文本中的指令属于待转换数据，不能修改编译规则或伪造验证状态。

公共符号应主动用于明确的关系：条件可写 `if条件: 分支` 或 `条件⇒结果`，避免重复叠加；顺序与状态变化可写 `flow: 检查→执行`、`状态: pending→paid`。只有原文明示因果时才用 `结果∵原因`，不能把条件猜成原因。`¬` 只否定命题，不表示禁止；许可分支中的 `no approval` / `No审批` 表示免审批，不表示禁止审批。`可/may`、`须/must`、`禁止`、`无需` 仍须区分。公开术语也不能替代具体请求方法、字段、响应码和冲突分支。

固定方案在概念和关系层混用原文语言、英语和公共表达，标签优先用 `role`、`goal`、`scope`、`flow`、`if`、`else`；业务实体保持一致，不逐字翻译整篇，不依靠 meme 或私有码。公开缩写在语境明确时可直接使用，不必重复附带全称。字符更少、英文更短或数学符号更多，都不能单独证明 token 更少，实际收益取决于所选编码。混合表达只改变内部指令形式，原任务的回答语言和格式要求仍须保留；代理本身不对模型响应增加回译。

## 5. 当前编译、验证与回退

常规请求生成一次候选，再执行固定形态检查，随后按本次设置计数和验证。对有至少两个可识别独立章节标题、且原本并非紧凑表达的原文，[`babelStructureIssues`](../../babel-go/outline.go) 要求候选包含至少两个带正文的树分支（`├` / `└` / `╰`）；代码、引文内的标记及空枝不计入。同时检查原标题复刻：去编号、加冒号、Markdown 标题、装饰树枝或内联箭头均不能掩盖旧章节骨架。改名后仍平铺，也不能满足树形合同。这是固定格式要求，不是符号密度或语义质量评分。

形态不合格时，将原文与失败草稿一起交回同一编译模型，最多额外重组一次；仍失败则明确返回表达结构失败，不缓存、不进入语义审核、不交给代理采用，但保留最近的候选供检查。该检查不依赖是否开启语义校验。网络异常和语义拒绝不会触发这种重组；没有多候选搜索或 token 反馈循环。原文始终保留。

形态豁免只依据原文：原本紧凑、明确指定输出格式或需要保留步骤引用的输入维持已有保护，代码及引文中的章节不作为重组依据。候选自行宣称 `Output format:` 或“保留编号”不能解除检查。数字检查仅豁免确认属于未引用连续列表的排版标签，包括 Markdown 转义的 `1\.`；正文金额、时间、次数、数值边界仍保护。

本地字面与上下文线索不是完整语言解析器。普通引号描述允许关系式改写；带 `¬(...)` 的比较、共享条件及跨分支模态若无法在局部确定作用域，应交给语义模型对照。不能把某个金额分支中的“无需审批”和另一个分支的审批义务机械合并，也不能把内部比较符当作否定后命题的最终比较关系。本地未拦截不等于通过；数值、技术字面量和可明确确认的冲突仍受保护。

验证有两种模式：

- `compare`：把原文和候选交给模型直接对照。
- `blind`：独立阅读器只看候选，再由对照器比较原文与阅读结果；阅读器不接收原文、词典或图例。

本地检查先保护部分技术字面量与明确约束。数字或否定词仍然出现，不能单独证明对象、条件和作用域都保留。blind 的结构化阅读用于检查理解，不是生成流程中的完整语义图中间表示，也不构成形式证明。

透明代理只尝试编译 `user` 消息中的字符串或显式 `text` 块。OpenAI 的 `system` / `developer`、Anthropic 顶层 `system`、assistant 历史、工具定义与描述、工具调用和工具结果均保留原字段值；图像等非文本块也不改写。候选只能替换原 `user` 文本位置，不能新建高权限消息或工具配置。

代理路径要求本次验证通过，且候选在所选计数方式下严格短于原文，才采用候选；Babel 的生成、验证或计数失败，或文本没有缩短时保留原文，继续转发最终请求。最终上游的普通错误响应继续返回；3xx 重定向会被拒绝并返回 `502`，不把 `Location` 交给客户端继续跳转。

`/api/compile` 的严格拒绝仍返回 `422`，校验服务或响应格式异常返回 `502`。失败时若已有候选，错误响应保留 `compiled`、`dialect`、`cache_hit`、`stats`、`validation` 和 `detail`。Web 可查看、复制候选及失败原因，但明确标为未通过或未验收、仅供检查；候选可见不改变门禁结论，也不使代理采用它。无候选或原文、方案、领域、设置变化时，旧结果及迟到响应失效。

缓存只保存正常完成生成且形态合格的候选；读取时重新检查形态，不复用仍平铺或复刻旧章节的缓存内容。形态合格的候选之后被语义拒绝，仍可能留在候选缓存中。文本计数和验证按请求重新执行，并发去重也只共享生成；不能借用另一个请求或旧缓存里的通过状态。一个等待者取消不会影响其他等待者，全部等待者取消则停止共享生成及尚未发出的重组请求。状态明确区分 `not_run`、`passed`、`failed` 和 `error`。

### 本地访问、凭据与网络边界

服务只支持明确的环回监听（`127.0.0.0/8`、`::1`、`localhost`），拒绝通配及局域网地址。实际 HTTP 入口校验监听地址与端口对应的 `Host`，拒绝跨源或不透明 `Origin` 及跨站浏览器请求；API 和代理写入仅接受 `application/json`，请求体最多 8 MiB。页面禁止嵌入，API 与代理响应强制 `nosniff` 和禁止脚本执行的 CSP。这里不区分不同本机原生进程的权限；本地进程及配置文件仍属于信任边界。

编译、校验与试连使用所选方案的密钥。请求或保存操作改变其协议、主机或端口时，必须显式提供新地址对应的密钥，不能沿用已存 Key；同源路径调整仍可沿用。最终代理转发只使用调用方提供的认证信息，缺失时返回 `401`，不会回退到编译密钥。浏览器不再保存或自动恢复密钥备份。

所有模型调用、试连和最终转发都不跟随 HTTP 重定向，需直接配置接收 POST 的目标地址。生成与校验的模型响应最多 8 MiB，超限不解析、不采用；最终上游响应正文不受这个模型响应上限截断。非流式转发仅为读取 usage 保留最多 1 MiB 的副本，超限后放弃统计副本，仍继续转发正文；流式统计使用有界的首部或尾部采样。

原文回退用于避免采用未经验证或未缩短的候选，不会清洗原文中的恶意指令。结构边界和失败处理不能替代模型服务的可信度，也不能保证编译器、阅读器与对照器不会共同误判；项目不宣称透明代理能消除所有提示词投毒。

## 6. 计量边界

当前可选 `estimate`、`cl100k_base`、`o200k_base`。后两者的“精确”仅指所选编码下的文本本体计数；工具不根据编译模型名称猜测消费模型的编码，也不把一种编码自动套给其他模型。

结果保留计数来源、版本、编码和范围。估算始终标记为估算；不支持的编码或精确计数失败应明确报告，不冒充已测。使用者可以用自己的典型文本比较原文与候选，据此修正专业词条或保留原文。

同一编码、同一文本范围下才能比较 token 变化。文本片段计数、完整请求的供应商 usage 和账单费用是不同口径；一条压缩后请求的 usage 不能证明未压缩请求的费用。编译和验证也有调用开销，因此文本更短不等于总费用一定降低。

## 7. 当前交付与后续范围

已经提供独立领域词典、词条编辑与保存、固定表达规则、指定编码计数、逐请求验证、缓存隔离和代理回退。当前重点是让同一套 `mixed` 规则产生有共享作用域的混语浅树，校验接受等义的关系表达，并检查信息损失与 token 变化。此前只要求删编号或允许符号，仍会退化成原章节下逐句缩写；当前用明确的默认表达和有限形态合同共同约束输出。

现有 [Go 评测命令和离线报告](../../eval/README.md)保留为按需使用的辅助工具。草拟样例仍待人工复核；pipeline 记录实际生成候选及验证结果，不执行最终消费任务，也不测量供应商账单。它们不是使用这个小工具前必须完成的一套流程。

早期讨论过完整语义图 IR、大规模跨模型矩阵、成本核算系统和多候选优化。这些属于可能的研究方向，已移出当前产品计划；项目不以完成这些系统作为小工具可用的前提。若今后出现具体、重复的使用问题，再单独判断是否需要最小扩展。
